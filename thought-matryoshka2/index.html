Thought Matryoshka 2 (working title)

Encoder-Native Prefix-Valid Latent Video Thoughts

Research plan · 작성 2026-08-23 · 이전 버전: Thought Matryoshka · 관련 축: VideoFlexTok, official code

Thought Matryoshka 1은 frozen encoder 뒤에 post-encoder thought adapter를 붙인다. Thought Matryoshka 2는 한 단계 더 들어간다: pretrained video encoder 자체가 latent thought registers를 품고, patch token을 중간 계산에만 쓰다가 최종적으로 prefix-valid thought tokens만 LLM에 내보낸다. 즉 "dense feature를 후처리"하는 것이 아니라, encoder가 처음부터 LLM이 읽을 생각을 토큰화한다.

1Core Idea

Thought Matryoshka 1

기존 video encoder는 그대로 둔다. encoder가 만든 dense feature X를 Ordered Thought Reader가 후처리해서 z1...zM을 만든다.

video → frozen encoder → dense X → thought reader → z1:zK → LLM

Thought Matryoshka 2

encoder 내부에 latent register를 넣고, patch token과 register가 매 layer 상호작용한다. 최종 출력은 patch가 아니라 ordered thought registers다.

video → latent-register encoder → z1:zK → LLM

왜 이 버전이 더 강한가
Representation is born compressed
post-processing으로 patch feature를 줄이는 게 아니라, encoder의 정보 흐름 자체가 latent thought bottleneck을 지나간다.
True tokenizer claim
VideoFlexTok이 generation용 flexible-length tokenizer라면, Thought Matryoshka 2는 reasoning용 flexible-length video thought tokenizer다.
Less duplicated compute
Matryoshka 1은 dense feature를 만든 뒤 다시 읽는다. Matryoshka 2는 encoder 내부에서 patch-to-latent exchange를 하므로 출력 단계의 별도 reader가 작아지거나 사라진다.

2Architecture

3Abstract (초안)

Current video LLMs typically inherit dense visual features from a pretrained encoder and compress them afterward, either by pruning, resampling, or learning a post-encoder adapter. This separation is convenient, but it makes compression an afterthought: the encoder first spends compute producing patch-level evidence that the LLM will never read. We propose Thought Matryoshka 2, an encoder-native latent tokenizer for video reasoning. Inspired by flexible-length tokenizers such as VideoFlexTok, we place ordered latent registers directly inside a pretrained video encoder and train the encoder so that every register prefix is a valid video state for an LLM. Patch tokens remain as internal scratch space, while the exported representation is a coarse-to-fine sequence of continuous thought tokens. Unlike reconstruction-oriented video tokenizers, our objective is not to regenerate pixels, but to preserve the information needed for multimodal reasoning: answer likelihood, full-token teacher distillation, semantic feature prediction, temporal predictive-state learning, and surgical prefix tests. The result is a video encoder that is born prefix-valid: it can emit one thought for gist, a few thoughts for event structure, or dozens for fine-grained evidence without a separate post-processing reader.

국문 요지. Matryoshka 1은 dense feature를 만든 뒤 thought reader로 읽는다. Matryoshka 2는 encoder 내부에 latent thought register를 넣고, nested prefix training을 encoder pretraining/fine-tuning 자체에 걸어버린다. patch token은 encoder 안에서만 쓰이는 작업 메모리이고, LLM에 나가는 것은 z1...zK thought prefix뿐이다. VideoFlexTok이 video generation을 위한 flexible tokenizer라면, Matryoshka 2는 video reasoning을 위한 flexible thought tokenizer다.

좋은 framing

"VideoFlexTok for reasoning"이라고 단순히 말하면 약하다. 더 정확한 문장은 이것이다: we replace reconstruction-valid flexible video tokens with reasoning-valid flexible video thoughts. 같은 nested-prefix 철학을 쓰지만, success metric이 pixel fidelity가 아니라 LLM reasoning accuracy, prefill budget, prefix monotonicity, multi-query amortization이다.

5Method

5.1 Latent Thought Registers Inside the Encoder

  • Register injection. 각 video segment 또는 latent frame마다 K개의 thought register를 넣는다. 가장 단순한 형태는 T × K temporal registers이고, 더 압축된 형태는 video-level global K registers다.
  • Patch-register exchange. encoder block마다 patch token은 local visual evidence를 업데이트하고, thought register는 cross-attention으로 patch evidence를 읽는다. patch는 내부 계산에 남지만 LLM 입력으로는 export하지 않는다.
  • Register ladder. register 간 attention에 coarse-to-fine bias를 준다. 앞 register는 넓은 시간/공간 범위를 보게 하고, 뒤 register는 앞 prefix가 놓친 residual detail을 읽게 한다.
  • Export. encoder 마지막 layer의 registers가 z1...zK가 된다. LLM은 z1:zk prefix와 question만 본다.

5.2 Prefix-Aware Attention

Matryoshka 2의 핵심은 register의 순서를 architecture에도 새기는 것이다. 단순히 loss로만 정렬을 기대하지 않고, attention 구조가 prefix hierarchy를 돕게 만든다.

  • Early-to-late residual mask. 뒤 register는 앞 register의 coverage map을 보고 아직 덜 설명된 patch/time region을 읽는다.
  • Monotone receptive field. z1은 전체 비디오, z2:z8은 주요 event, z9+는 local detail에 더 집중하도록 weak prior를 둔다.
  • Prefix dropout inside encoder. 학습 중 suffix register를 drop하면 뒤 register가 없는 상태로도 encoder block이 작동해야 하므로, 앞 register가 완성된 state가 된다.

5.3 Training Objectives

L = E_k [ L_QA(z1:zk) + α KL(full-token teacher || prefix student) ] + β L_sem + γ L_pred + δ L_order + η L_recon(optional)

  • Nested prefix QA. k∈{1,2,4,8,16,32,64}를 샘플하고, 각 prefix가 answer likelihood를 직접 최적화한다.
  • Full-token teacher distillation. 기존 full visual-token model을 teacher로 두고, prefix student가 answer distribution과 일부 hidden state를 따라가게 한다.
  • Semantic feature target. VideoFlexTok이 semantic bias를 쓰듯, early registers가 DINO/SigLIP/InternVideo style semantic feature를 예측하게 한다. reconstruction만 걸면 앞 token이 texture에 끌릴 수 있다.
  • Predictive state. thought prefix가 다음 segment의 semantic feature 또는 entity/event state를 예측하게 한다. reasoning에는 frame reconstruction보다 dynamics state가 중요하다.
  • Optional reconstruction. encoder pretraining 안정화를 위해 lightweight decoder를 붙일 수 있지만, 메인 objective는 pixel fidelity가 아니라 LLM reasoning이다.

6Pretraining / Adaptation Plan

Stage 0 - Retrofit a pretrained encoder
  • SigLIP/Qwen2.5-VL vision tower에 register tokens와 small adapter blocks를 삽입.
  • 기존 patch pathway는 freeze 또는 low-rank update.
  • register pathway만 먼저 학습해 catastrophic forgetting을 줄임.
Stage 1 - Encoder-native tokenizer pretraining
  • unlabeled video에서 semantic feature prediction, temporal predictive state, optional reconstruction 학습.
  • nested dropout을 encoder 내부 register에 직접 적용.
  • 목표: z1부터 coarse-to-fine 정보가 생기는지 probing.
Stage 2 - LLM alignment
  • LLM은 frozen, register-to-LLM projector와 register adapter를 학습.
  • Video QA로 random-prefix CE와 teacher KL 적용.
  • budget별 Pareto curve를 만든다.
Stage 3 - Native deployment
  • inference에서는 dense patch 출력 자체를 만들지 않거나 export하지 않음.
  • 긴 영상은 time-causal/sliding encoder로 streaming thought cache 생성.
  • multi-query setting에서 thought prefix만 재사용.

8Experiments

E1 - Native vs post-encoder Matryoshka

주장: encoder-native register는 같은 thought budget에서 post-encoder reader보다 더 좋은 accuracy/latency tradeoff를 만든다.

  • Compare Matryoshka 1 reader vs Matryoshka 2 native registers with matched parameter count.
  • Report prefill tokens, encoder FLOPs, reader FLOPs, TTFT, total latency.
  • Important: native version must show total cost, not only LLM prefill cost.

E2 - Prefix monotonicity

주장: encoder 내부 nested dropout이 z1, z1:z2, z1:z4, ...의 안정적인 성능 곡선을 만든다.

  • Metrics: accuracy vs prefix length, calibration vs prefix length, representation similarity across prefixes.
  • Ablations: no nested dropout, loss-only ordering, no register ladder, no semantic target.

E3 - Semantic-first, detail-later probing

주장: early registers capture event/semantic structure; later registers add OCR, small objects, fine detail.

  • Probe early vs late registers for action, object, scene, motion, OCR, counting.
  • Attention/coverage visualization: early broad, late local.
  • Compare with VideoFlexTok-style reconstruction tokens to separate reasoning vs reconstruction bias.

E4 - Multi-query and streaming

주장: native thought registers can be cached as reusable video memory.

  • Same video with 1/5/20/100 questions.
  • Long video sliding-window encoding with temporal register carryover.
  • Cost curve against full-token VLM, pruning, Matryoshka 1, and caption-note baselines.

9리스크와 방어선

  • R1 Pretraining cost가 커진다. Matryoshka 1은 adapter 학습이면 되지만, 2는 encoder-native라 더 비싸다. 그래서 retrofit path: 기존 encoder freeze + register path 학습부터 시작한다.
  • R2 VideoFlexTok와 너무 비슷해 보일 수 있다. reconstruction tokenizer가 아니라 reasoning tokenizer임을 objective, benchmarks, LLM interface로 분리해야 한다.
  • R3 Patch 정보가 너무 빨리 사라질 수 있다. patch는 내부 scratch token으로 충분히 유지하되, LLM export만 thought로 제한한다.
  • R4 Host-specific plugin성이 약해진다. 대신 encoder 자체를 배포하는 tokenizer claim을 얻는다. Matryoshka 1은 plug-in baseline, 2는 native model variant로 포지셔닝한다.
  • R5 짧은 video QA에서 효율 이득이 작을 수 있다. long video, multi-query, large LLM prefill, streaming cache를 메인 setting으로 둔다.
내 판단

Matryoshka 2는 더 fancy하고 근본적인 아이디어다. 다만 first submission 전략은 둘을 경쟁시키기보다, Matryoshka 1 = immediately testable adapter, Matryoshka 2 = encoder-native extension inspired by flexible tokenization으로 두는 게 안전하다. 2가 잘 되면 논문 제목은 "Encoder-Native Thought Tokenization" 쪽으로 가도 된다.
