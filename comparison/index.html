Video LLM에서 Prefill 이전의 Dynamic Visual Token 연구 비교 Dynamic Visual Tokens before LLM Prefill in Video Understanding

비주얼 토큰을 LLM prefill 전에 동적으로 줄이거나 할당하는 방법들 — 어디서 dynamic해지는가(encoder 수정 vs post-hoc), 그리고 토큰 수가 자동으로 가변인가(content-adaptive) vs 정해진 budget 안에서 선택만 dynamic인가. Methods that dynamically reduce or allocate visual tokens before the LLM prefill stage — where the dynamism comes from (modified encoder vs. post-hoc), and whether the token count is automatically content-adaptive or a predetermined budget where only the selection is dynamic.

최종 갱신: 2026-08-19 · 근거: 각 논문 arXiv/공식 저장소 + TMLR 2026 토큰 압축 서베이(arXiv:2507.20198) 및 관련 awesome-list 교차 검증 Last updated 2026-08-19 · Sources: each paper's arXiv page / official repo, cross-checked against the TMLR 2026 token-compression survey (arXiv:2507.20198) and related awesome-lists

범위. "prefill 전"은 비주얼 토큰이 LLM에 들어가기 전 단계(vision encoder 내부·출력, projector/connector, frame selection)에서 토큰이 줄어드는 것을 뜻한다. FastV처럼 LLM layer 안에서 pruning하는 방법과 KV cache/decoding 단계 방법은 §6에 경계 사례로만 정리했다. 학습 기준은 "scratch부터 새로 학습한 것만 제외" — training-free(post-hoc)와 pretrained encoder+LLM 위에 모듈을 fine-tune한 것 모두 포함. Scope. "Before prefill" means token reduction happening before visual tokens enter the LLM (inside/at the output of the vision encoder, at the projector/connector, or via frame selection). Methods that prune inside LLM layers (e.g., FastV) and KV-cache/decoding-stage methods are listed only as boundary cases in §6. Training criterion: everything except from-scratch training is in scope — both training-free (post-hoc) methods and modules fine-tuned on pretrained encoder+LLM.

3Encoder/Connector를 학습해서 dynamic (pretrained 위 fine-tune)Dynamic via a trained encoder/connector (fine-tuned on pretrained components)

dynamic함이 학습된 모듈(projector/connector/resampler/인코더 내부 모듈)에서 나오는 계열. 전부 pretrained encoder+LLM 위 fine-tune이며 from-scratch는 없음. "형성만 dynamic"인 것(개수 고정)과 "개수까지 adaptive"인 것을 구분할 것 — 제목에 dynamic이 들어가도 개수가 고정인 경우가 많다. Dynamism comes from a trained module (projector/connector/resampler or in-encoder module). All are fine-tunes on pretrained encoder+LLM — none from scratch. Distinguish "dynamic formation only" (fixed count) from "count-adaptive" — many titles say "dynamic" while the count is fixed.

  • "진짜" content-adaptive한 토큰 수(threshold·클러스터·그래프가 개수를 결정)는 소수다: training-free 쪽은 STTM, DynTok, LLaVA-Scissor, DyMU, METok, PruneVid(병합 단계), TimeChat-Online DTD 정도, 학습 쪽은 LongVU, Quicksviewer, DynFocus, LangDC, VQToken(adaptive 모드), AdaCM², SlowFocus(query 구간 기준) 정도.Genuinely content-adaptive counts (threshold/cluster/graph decides how many) are the minority: training-free — STTM, DynTok, LLaVA-Scissor, DyMU, METok, PruneVid (merging stage), TimeChat-Online DTD; trained — LongVU, Quicksviewer, DynFocus, LangDC, VQToken (adaptive mode), AdaCM², SlowFocus (query-segment).
  • 제목의 "dynamic"은 대부분 "어떤 토큰인지"가 dynamic이라는 뜻이다: DyCoke·VisionZip·ToDRE·AKS·BOLT는 개수/비율 고정, VidCom²·FastVID·HoliTom·QuoTA·KVTP·Q-Frame은 총 budget 고정 + 할당만 dynamic. Chat-UniVi·TESTA도 클러스터/비율 하이퍼파라미터가 개수를 고정한다."Dynamic" in titles usually means which tokens, not how many: DyCoke, VisionZip, ToDRE, AKS, BOLT fix the count/ratio; VidCom², FastVID, HoliTom, QuoTA, KVTP, Q-Frame fix the total budget and adapt only allocation. Chat-UniVi and TESTA also pin the count via cluster/ratio hyperparameters.
  • encoder를 실제로 고치는 경우는 드물다: post-hoc 계열은 전부 encoder 밖(출력)에서 동작하고, 학습 계열도 대부분 encoder는 frozen인 채 connector/projector만 학습한다. encoder 내부까지 들어가는 것은 TESTA(블록 내 aggregation), DyMU(ViT 층 병합, TF), Qwen2-VL/Oryx(native-resolution ViT) 정도.Few methods actually modify the encoder: post-hoc methods all operate at/after the encoder output, and most trained methods keep the encoder frozen and train only the connector/projector. Inside-the-encoder work is limited to TESTA (in-block aggregation), DyMU (ViT-layer merging, TF), and Qwen2-VL/Oryx (native-resolution ViTs).
  • 세 번째 가변 유형을 혼동하지 말 것: Qwen2-VL/2.5-VL·Oryx·Dynamic-VLM의 토큰 수 가변은 입력 크기/길이/지정 비율 기반이지 내용 중요도 기반이 아니다.Don't conflate the third regime: the variable counts of Qwen2-VL/2.5-VL, Oryx, and Dynamic-VLM come from input size/length/on-demand ratios, not content saliency.
  • 호스트 모델 관례: training-free 계열의 사실상 표준 테스트베드는 LLaVA-OneVision/LLaVA-Video(Qwen2 + SigLIP)와 Qwen2-VL/2.5-VL이다.Host-model convention: the de-facto testbeds for training-free methods are LLaVA-OneVision / LLaVA-Video (Qwen2 + SigLIP) and Qwen2-VL / 2.5-VL.
