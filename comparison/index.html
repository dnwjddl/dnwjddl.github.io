Video LLM에서 Prefill 이전의 Dynamic Visual Token 연구 비교 Dynamic Visual Tokens before LLM Prefill in Video Understanding

비주얼 토큰을 LLM prefill 전에 동적으로 줄이거나 할당하는 방법들 — 어디서 dynamic해지는가(encoder 수정 vs post-hoc), 그리고 토큰 수가 자동으로 가변인가(content-adaptive) vs 정해진 budget 안에서 선택만 dynamic인가. Methods that dynamically reduce or allocate visual tokens before the LLM prefill stage — where the dynamism comes from (modified encoder vs. post-hoc), and whether the token count is automatically content-adaptive or a predetermined budget where only the selection is dynamic.

범위. "prefill 전"은 비주얼 토큰이 LLM에 들어가기 전 단계(vision encoder 내부·출력, projector/connector, frame selection)에서 토큰이 줄어드는 것을 뜻한다. FastV처럼 LLM layer 안에서 pruning하는 방법과 KV cache/decoding 단계 방법은 §7에 경계 사례로만 정리했다. 학습 기준은 "scratch부터 새로 학습한 것만 제외" — training-free(post-hoc)와 pretrained encoder+LLM 위에 모듈을 fine-tune한 것 모두 포함. Scope. "Before prefill" means token reduction happening before visual tokens enter the LLM (inside/at the output of the vision encoder, at the projector/connector, or via frame selection). Methods that prune inside LLM layers (e.g., FastV) and KV-cache/decoding-stage methods are listed only as boundary cases in §7. Training criterion: everything except from-scratch training is in scope — both training-free (post-hoc) methods and modules fine-tuned on pretrained encoder+LLM.

8핵심 관찰Key takeaways

  • "진짜" content-adaptive한 토큰 수(threshold·클러스터·그래프가 개수를 결정)는 여전히 소수다: training-free 쪽은 STTM, DynTok, LLaVA-Scissor, DyMU, METok, PruneVid(병합 단계), TimeChat-Online DTD에 2026년의 GSTEP, ST-SimDiff, TTF, AOT, FlashVID, KTV, AdaptToken, MeToM이 더해졌고, 학습 쪽은 LongVU, Quicksviewer, DynFocus, LangDC, VQToken(adaptive 모드), AdaCM², SlowFocus에 AutoGaze, ONCE, CRAFT, Tempo가 더해졌다.Genuinely content-adaptive counts (threshold/cluster/graph decides how many) remain the minority: training-free — STTM, DynTok, LLaVA-Scissor, DyMU, METok, PruneVid (merging stage), TimeChat-Online DTD, joined in 2026 by GSTEP, ST-SimDiff, TTF, AOT, FlashVID, KTV, AdaptToken, MeToM; trained — LongVU, Quicksviewer, DynFocus, LangDC, VQToken (adaptive mode), AdaCM², SlowFocus, joined by AutoGaze, ONCE, CRAFT, Tempo.
  • 제목의 "dynamic"은 대부분 "어떤 토큰인지"가 dynamic이라는 뜻이다: DyCoke·VisionZip·ToDRE·AKS·BOLT는 개수/비율 고정, VidCom²·FastVID·HoliTom·QuoTA·KVTP·Q-Frame은 총 budget 고정 + 할당만 dynamic. Chat-UniVi·TESTA도 클러스터/비율 하이퍼파라미터가 개수를 고정한다."Dynamic" in titles usually means which tokens, not how many: DyCoke, VisionZip, ToDRE, AKS, BOLT fix the count/ratio; VidCom², FastVID, HoliTom, QuoTA, KVTP, Q-Frame fix the total budget and adapt only allocation. Chat-UniVi and TESTA also pin the count via cluster/ratio hyperparameters.
  • encoder 내부 개입은 2023–25년엔 드물었지만(TESTA, DyMU 정도) 2025 말–2026년에 하나의 흐름이 됐다 (§4): LiteFrame(압축 내재화 distillation), AutoGaze(ViT 앞 patch 선택, content-adaptive), IPCV·LUVC(ViT 층 내 TF pruning/병합), LaCo(층간 pixel-shuffle), EarlyTom(encoder 층 내 병합). 논거도 공통적이다 — post-hoc으로 LLM 쪽을 줄이면 병목이 ViT의 프레임당 연산으로 옮겨간다는 것.Encoder-internal work was rare in 2023–25 (TESTA, DyMU) but became a real wave in late 2025–2026 (§4): LiteFrame (compression internalized via distillation), AutoGaze (patch selection before the ViT, content-adaptive), IPCV/LUVC (TF pruning/merging in ViT layers), LaCo (inter-layer pixel-shuffle), EarlyTom (merging inside encoder layers). The shared argument: post-hoc LLM-side reduction just shifts the bottleneck to the ViT's per-frame compute.
  • 세 번째 가변 유형을 혼동하지 말 것: Qwen2-VL/2.5-VL·Oryx·Dynamic-VLM의 토큰 수 가변은 입력 크기/길이/지정 비율 기반이지 내용 중요도 기반이 아니다.Don't conflate the third regime: the variable counts of Qwen2-VL/2.5-VL, Oryx, and Dynamic-VLM come from input size/length/on-demand ratios, not content saliency.
  • 호스트 모델 관례: training-free 계열의 사실상 표준 테스트베드는 LLaVA-OneVision/LLaVA-Video(Qwen2 + SigLIP)와 Qwen2-VL/2.5-VL이다.Host-model convention: the de-facto testbeds for training-free methods are LLaVA-OneVision / LLaVA-Video (Qwen2 + SigLIP) and Qwen2-VL / 2.5-VL.
