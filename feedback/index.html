Training Data Feedback

LLaVA-Video-178K를 Thought Matryoshka 학습 데이터로 쓰는 법

Research note · 작성 2026-08-23 · 관련 페이지: Thought Matryoshka 2

결론은 단순하다. 다른 데이터셋을 꼭 새로 찾자는 말이 아니라, LLaVA-Video-178K를 main training data로 쓰되 random mixing하지 말고 내부 sample type을 나눠서 curriculum으로 쓰자. Caption, open-ended QA, multiple-choice QA, temporal-heavy QA를 stage별로 다르게 써야 thought register가 static image summary가 아니라 video state를 배운다.

Read first

이 체크리스트는 TM2 실험이 "진짜 구현"인지 확인하기 위한 것이다. 하나라도 STOP 항목에 걸리면 결과를 논문/보고서 수치로 쓰지 말고 debug run으로만 표시한다.

# TM2 Implementation Audit Checklist

## 0. Run Identity
- [ ] Experiment name, date, machine, GPU count, code commit, config file path가 기록되어 있다.
- [ ] 모든 표/그래프 값은 script가 만든 log/eval JSON에서 온다. 사람이 손으로 추정해서 적은 값이 아니다.
- [ ] 아직 측정하지 않은 값은 "planned", "not measured", "N/A"로 표시한다. 실측값인 척하지 않는다.
- [ ] output directory에 config.yaml, git commit, train log, eval log, dataset manifest, checkpoint path가 함께 저장된다.

## 1. Dataset Integrity
- [ ] Main train source는 LLaVA-Video-178K이며 실제 data root와 manifest path를 기록했다.
- [ ] caption / openQA / MCQA / temporal-heavy / static-easy pool을 큰 pool로 나누었다. tiny subset 1k-2k개를 main training으로 쓰지 않는다.
- [ ] 각 pool의 sample count를 출력했다: caption N, openQA N, MCQA N, temporal-heavy N, static-easy N.
- [ ] Stage별 dataloader가 pool에서 비율대로 sample한다. 작은 filtered json 하나만 10 epoch 반복하지 않는다.
- [ ] global batch 128 기준으로 steps_per_epoch = loaded_samples / 128 계산이 맞다.
- [ ] "10 epochs = 125 steps"처럼 나오면 STOP: loaded_samples가 약 1,600개뿐이라는 뜻이다.
- [ ] train/eval split leakage를 확인했다. VideoMME, MVBench, LongVideoBench, held-out NeXT-QA/ActivityNetQA가 train에 섞이지 않는다.
- [ ] temporal-heavy filtering rule을 저장했다. keyword만 대충 고른 경우 sample 100개를 수동 검토했다.
- [ ] failed/missing video 개수와 drop rate를 로그로 남겼다.

## 2. Real Video Loading
- [ ] 실제 video file을 decode한다. random tensor, blank frame, duplicated dummy image, synthetic placeholder를 쓰지 않는다.
- [ ] dataloader에서 샘플 video 16개를 저장/시각화해서 실제 프레임이 들어오는지 확인했다.
- [ ] frame count, sampled frames, fps/segment policy, resolution, crop policy가 config에 기록되어 있다.
- [ ] feature cache를 쓴다면 cache가 실제 video에서 생성되었고, video id, encoder name, layer, feature shape, checksum을 가진다.
- [ ] online encoder output과 cached feature output을 같은 video 8개에서 비교했다.

## 3. Student Architecture
- [ ] Student path는 Video -> frozen vision encoder -> temporal thought graft -> z1...zM -> projector -> frozen LLM -> answer 구조다.
- [ ] Vision encoder checkpoint 이름을 기록했다. 예: SigLIP / Qwen2.5-VL vision tower / InternVideo 계열.
- [ ] encoder의 어느 layer feature를 쓰는지 사전에 정했다. "그냥 아무 layer"를 쓰지 않는다.
- [ ] 선택한 encoder layer의 feature shape가 로그에 출력된다: B, T, N_patch, d_v.
- [ ] LLM checkpoint 이름을 기록했다. toy LM, random LM, tiny debugging LM을 main result로 쓰지 않는다.
- [ ] LLM은 frozen이다. trainable parameter list에 LLM weight가 포함되지 않는다.
- [ ] main run은 M_max=128 thought registers를 사용한다. M_max=64는 cheap sanity 또는 extreme compression ablation이다.
- [ ] trainable modules는 thought registers, temporal graft, projector, optional temporal prediction head뿐이다.
- [ ] trainable parameter count와 frozen parameter count가 출력된다.
- [ ] Temporal graft는 video patch features를 cross-attention으로 읽는다. 단순 mean pooling만 하고 "thought"라고 부르지 않는다.
- [ ] register self-attention은 causal/prefix-safe하다. early register가 later register 정보를 볼 수 없다.
- [ ] nested prefix dropout은 output에서만 자르는 것이 아니라 forward 안에서 first k registers만 존재하게 한다.
- [ ] TM2 thought-only path에서는 raw patch tokens가 LLM prefill로 들어가지 않는다.

## 4. Prefix Training
- [ ] Main training에서 k in {8,16,32,64,128}를 sample한다.
- [ ] 각 k가 실제로 batch에 얼마나 나왔는지 histogram을 저장한다.
- [ ] LLM input에는 z1:zk만 들어간다. z(k+1):zM 정보가 attention/mask를 통해 leak되지 않는다.
- [ ] 같은 sample에서 k를 바꾸면 input token count가 실제로 바뀌는 unit test가 있다.
- [ ] prefix별 loss/accuracy를 따로 로깅한다: k=8,16,32,64,128.

## 5. Losses
- [ ] L_answer: answer CE가 실제 ground-truth answer token에 걸린다.
- [ ] L_teacher_KL: full visual-token teacher logits와 student logits 사이 KL이 계산된다.
- [ ] L_order: 긴 prefix가 짧은 prefix보다 더 나쁘면 penalty가 생긴다.
- [ ] L_semantic: thought pool이 frozen semantic target을 예측한다. target 모델과 layer를 기록했다.
- [ ] L_pred: temporal prediction을 쓰는 경우 next segment target이 같은 video의 다음 segment에서 온다.
- [ ] 각 loss weight lambda를 config에 기록했다.
- [ ] per-loss scalar가 train log에 찍힌다. 항상 0이거나 NaN이면 STOP.
- [ ] teacher 없이 학습한 run은 "no-teacher ablation"으로만 표시한다. main result로 쓰지 않는다.

## 6. Teacher Model
- [ ] Teacher는 no-grad eval mode의 full visual-token VLM이다. 예: Qwen2.5-VL or LLaVA-OneVision.
- [ ] teacher는 dense/full visual input을 본다. student thought prefix만 보고 만든 output을 teacher로 쓰지 않는다.
- [ ] teacher logits cache는 video id, question id, answer options, model checkpoint, timestamp를 포함한다.
- [ ] teacher/student token alignment와 KL temperature를 기록했다.
- [ ] teacher cache miss rate를 기록했다.

## 7. Training Schedule
- [ ] Stage 1 warm-up: 3k-5k steps, caption 64 + easy openQA 64 per global batch 128.
- [ ] Stage 2 main prefix: 20k-30k steps, openQA 64 + MCQA 32 + caption/summary 16 + temporal QA 16.
- [ ] Stage 3 temporal refine: 7k-10k steps, temporal/order/state-change/counting 중심 oversampling.
- [ ] Stage 4 teacher-KL strengthen: 5k-10k steps, openQA 48 + MCQA 32 + temporal-heavy 32 + caption/summary 16.
- [ ] trainer는 num_train_epochs보다 max_steps 중심으로 종료한다.
- [ ] global batch = per_device_batch * grad_accum * num_gpus 계산이 맞다.
- [ ] optimizer, LR, scheduler, warmup, precision, gradient clipping, seed가 config에 기록되어 있다.
- [ ] total sample-visits = max_steps * global_batch가 보고된다.

## 8. Pareto Evaluation
- [ ] 같은 checkpoint 하나를 k=8,16,32,64,128로 여러 번 평가한다. budget마다 별도 모델을 train하지 않는다.
- [ ] x축에는 actual prefill tokens를 둔다. 괄호로 full visual-token baseline 대비 percent를 같이 표시한다.
- [ ] retention/pruning baseline과 비교할 때 label은 5%, 10%, 25%, 50%, 100%로 맞춘다.
- [ ] TM2의 percent는 k/128 thought prefix ratio이고, retention baseline의 percent는 retained raw visual token ratio다. 둘을 혼동하지 않는다.
- [ ] TTFT/latency/memory 값은 실제 timing script로 측정한다. FLOP 추정값이면 estimated라고 표시한다.
- [ ] prefix monotonicity plot을 만든다: k가 커질수록 accuracy가 대체로 올라가는지 확인한다.

## 9. Baselines
- [ ] Full visual-token VLM baseline을 같은 eval split과 prompt로 돌렸다.
- [ ] Fixed latent resampler baseline을 같은 thought/token budget으로 돌렸다.
- [ ] Token pruning/retention baseline을 5%, 10%, 25%, 50% retention으로 돌렸다.
- [ ] Caption/note baseline을 쓰면 caption 생성 비용과 LLM prefill 비용을 따로 보고한다.
- [ ] 모든 baseline은 같은 decoding config를 사용한다: temperature, top_p, max_new_tokens, prompt template.

## 10. Evaluation Integrity
- [ ] Eval datasets: VideoMME, MLVU, MVBench, EgoSchema, LongVideoBench, held-out NeXT-QA/ActivityNetQA 등 버전과 split을 기록한다.
- [ ] eval script path와 command를 저장했다.
- [ ] raw prediction JSON, scored result JSON, aggregate CSV가 저장된다.
- [ ] 정확도뿐 아니라 prefill tokens, TTFT, memory, encode time, LLM time을 분리 보고한다.
- [ ] "best checkpoint" 선택 기준을 eval 전에 정했다.
- [ ] 실패 사례를 최소 20개 확인해서 video loading / prompt / answer parsing 오류가 아닌지 본다.

## 11. Sanity Tests
- [ ] Random video / zero video를 넣으면 accuracy가 떨어진다.
- [ ] 같은 question에 다른 video를 넣으면 answer가 바뀐다.
- [ ] frame order를 shuffle/reverse하면 temporal-heavy QA 성능이 떨어진다.
- [ ] z tokens를 제거할수록 성능이 떨어지는지 확인한다.
- [ ] z1:z8과 z1:z128의 attention/activation이 실제로 다르다.
- [ ] 256-sample overfit run에서 loss가 내려가는지 확인했다.
- [ ] feature cache와 online encoder가 같은 answer를 낸다.

## 12. STOP Conditions
- [ ] STOP if 실제 video decode 없이 random/cached dummy tensor로 학습했다.
- [ ] STOP if main training total steps가 1k 이하인데 main result라고 주장한다.
- [ ] STOP if 10 epochs가 125 steps처럼 나온다.
- [ ] STOP if encoder layer/checkpoint가 명시되어 있지 않다.
- [ ] STOP if LLM이 random/tiny placeholder인데 real LLM result처럼 적었다.
- [ ] STOP if teacher logits가 없는데 teacher distillation을 했다고 적었다.
- [ ] STOP if Pareto/latency/TTFT가 실측이 아니라 추정인데 measured처럼 적었다.
- [ ] STOP if eval split이 train data와 겹친다.
- [ ] STOP if raw visual patch tokens가 LLM에 들어가는데 thought-only TM2라고 주장한다.

## 13. Minimum Artifact Bundle
- [ ] config.yaml
- [ ] dataset_manifest.json with pool counts
- [ ] train.log with step count, batch mix, prefix k histogram, per-loss scalars
- [ ] model_summary.txt with trainable/frozen parameter counts
- [ ] teacher_cache_manifest.json
- [ ] eval_predictions.json
- [ ] eval_scores.csv
- [ ] latency_report.json
- [ ] pareto_curve.csv
- [ ] checkpoint path and git commit hash

1Verdict

Use it

LLaVA-Video-178K는 좋은 시작점

QA/caption format이 이미 instruction tuning 형태이고, open-ended QA와 multiple-choice QA가 같이 있어 TM2-lite의 first training data로 적합하다.

Do not random mix

그냥 전체를 섞으면 claim이 약해짐

Static scene/object QA가 너무 많으면 register가 video thought가 아니라 image summary token처럼 배울 수 있다.

정확한 framing.

Main training data = LLaVA-Video-178K

But split it internally into large pools:
caption
open-ended QA
multiple-choice QA
temporal-heavy QA
static/object/scene QA

Important:
"split" does not mean making a tiny 1k-2k subset.
It means building samplers over the large internal pools.

4Concrete Step Schedule

TM2-lite first run 기준. 1 optimizer step은 global batch 128 video-text samples로 둔다. 학습 종료는 epoch보다 max_steps로 제어한다. 먼저 30k steps로 sanity check를 보고, prefix curve가 보이면 55k steps까지 확장한다.

Prefix size recommendation

M_max=64는 cheap sanity check에는 괜찮지만, main result에는 너무 aggressive하게 보일 수 있다. 메인 실험은 M_max=128로 두고, k ∈ {8,16,32,64,128}를 쓰는 것이 더 안전하다. 64-slot 결과는 "extreme compression" ablation으로 남기고, 128-slot 결과를 primary Pareto curve로 보고한다.

Epoch warning

10 epochs = 125 steps처럼 보이면 full LLaVA-Video-178K를 학습하는 것이 아니다. epoch당 12.5 steps라는 뜻이고, global batch 128이면 dataloader에 실제로 들어간 데이터가 약 12.5 × 128 = 1,600 samples뿐이라는 신호다. TM2 curriculum의 "나눠서 학습"은 작은 subset을 10 epoch 반복하라는 뜻이 아니라, 큰 caption/openQA/MCQA/temporal-heavy pool에서 정해진 비율로 계속 sample하라는 뜻이다.

steps_per_epoch = len(train_dataset_or_pool) / global_batch
total_steps = steps_per_epoch × epochs

If total_steps is tiny:
check max_steps, limit_train_batches, debug_subset,
and whether only one small filtered json was loaded.

5Pareto Budget Evaluation

Accuracy vs token budget plot은 percentage로 보여주는 것이 좋다. 다만 TM2는 prefix model이므로 실제 inference는 arbitrary token pruning이 아니라 z1:zk prefix 선택으로 한다. 메인 figure는 M_max=128 기준으로 5%, 10%, 25%, 50%, 100% budget label을 붙이고, 내부 구현은 가장 가까운 prefix 길이 k로 매핑한다.

Why percentage labels matter.

기존 token pruning / merging / retention 연구들은 보통 "retain 5%, 10%, 25% of visual tokens"처럼 보고한다. 그래서 TM2도 Pareto plot에서는 같은 언어를 써야 직접 비교가 쉽다. 차이는 이것이다: retention baseline의 10%는 raw visual evidence 중 10%를 남기는 것이고, TM2의 ~10%는 learned thought prefix 중 앞 10% 정도만 읽는 것이다. 따라서 table에는 retention ratio, actual prefill tokens, accuracy를 같이 보고한다.

Plot labelTM2 prefix, M=128Actual thought ratioUse caseNote
~5% z1:z8 6.25% Very cheap gist / fast answer 5%에 가장 가까운 power-of-two prefix. z1:z4도 optional ultra-low point로 추가 가능.
~10% z1:z16 12.5% Main low-budget point 논문 punchline에 좋은 구간. 수천 visual tokens 대비 십여 개 thought tokens.
25% z1:z32 25% Balanced accuracy / cost point 많은 benchmark에서 가장 중요한 operating point가 될 가능성이 높다.
50% z1:z64 50% Careful reasoning 세부 temporal/OCR/counting 질문에서 성능 회복을 확인한다.
100% z1:z128 100% Full thought budget TM2의 maximum thought representation. Full visual-token baseline과는 별도로 표시한다.

Plotting rule.

# Evaluate the same checkpoint multiple times.
# Do not train a separate model for each budget.
for k in [8, 16, 32, 64, 128]:
    answer = frozen_llm(project(z[:, :k]), question)
    report accuracy, TTFT, and prefill_tokens

# Main x-axis:
actual video prefill tokens = k + special_video_tokens

# Also annotate:
% of full visual-token baseline =
100 * TM2_video_prefill_tokens / full_VLM_visual_prefill_tokens

중요한 점은 두 percent를 헷갈리지 않는 것이다. k/128는 TM2 내부 thought budget ratio이고, TM2 prefill / full visual-token prefill은 full VLM 대비 실제 token 절감률이다. 논문 figure에는 absolute token count와 full-baseline percentage를 같이 쓰면 가장 방어하기 쉽다.

7Loss Design

데이터 curriculum과 loss는 같이 가야 한다. LLaVA-Video-178K는 thought token 자체를 supervise하지 않으므로, teacher distillation과 prefix-order pressure가 필요하다.

L = L_answer
  + λ_kl L_teacher
  + λ_order L_prefix_order
  + λ_sem L_semantic
  + λ_pred L_temporal_prediction
CE

Answer loss

Video understanding task의 main objective. 답을 못하면 thought가 의미 없다.

KL

Teacher distillation

Dense visual-token teacher의 판단을 few thought tokens로 압축하게 만든다.

Order

Prefix order loss

긴 prefix가 짧은 prefix보다 더 못하면 penalty를 준다.

8Train / Eval Split

Training은 LLaVA-Video-178K 하나로 시작해도 된다. 다만 evaluation은 별도 benchmark로 보고, LLaVA-Video-178K repo 안에 포함된 public QA split과 겹치지 않게 관리해야 한다.

Leakage risk

LLaVA-Video-178K repository에는 NeXT-QA, ActivityNetQA, PerceptionTest 같은 public QA도 재현용으로 같이 들어가 있다. train에 쓴 split과 eval benchmark가 겹치면 결과가 방어되지 않는다. 논문에서는 train source, held-out split, evaluation-only benchmark를 명확히 적어야 한다.

9Final Recommendation

LLaVA-Video-178K 하나로 시작해도 된다. 대신 random mixing이 아니라 caption/openQA/MCQA/temporal-heavy로 curriculum을 짜고, 후반에는 temporal-heavy sample을 oversampling한다. 첫 sanity check는 30k steps, 제대로 된 first run은 55k steps로 두고, evaluation은 5/10/25/50/100% budget-style Pareto curve로 보여준다. 이 위에 teacher distillation, nested prefix loss, temporal prediction loss를 같이 걸어야 Thought Matryoshka의 핵심 claim이 살아난다.
Short version: use LLaVA-Video-178K as the main instruction-alignment data, not as an unstructured random pool. Split it by task type, over-sample temporal-heavy QA late in training, and evaluate on clean held-out video understanding benchmarks.
