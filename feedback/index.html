Training Data Feedback

LLaVA-Video-178K를 Thought Matryoshka 학습 데이터로 쓰는 법

Research note · 작성 2026-08-23 · 관련 페이지: Thought Matryoshka 2

결론은 단순하다. 다른 데이터셋을 꼭 새로 찾자는 말이 아니라, LLaVA-Video-178K를 main training data로 쓰되 random mixing하지 말고 내부 sample type을 나눠서 curriculum으로 쓰자. Caption, open-ended QA, multiple-choice QA, temporal-heavy QA를 stage별로 다르게 써야 thought register가 static image summary가 아니라 video state를 배운다.

1Verdict

Use it

LLaVA-Video-178K는 좋은 시작점

QA/caption format이 이미 instruction tuning 형태이고, open-ended QA와 multiple-choice QA가 같이 있어 TM2-lite의 first training data로 적합하다.

Do not random mix

그냥 전체를 섞으면 claim이 약해짐

Static scene/object QA가 너무 많으면 register가 video thought가 아니라 image summary token처럼 배울 수 있다.

정확한 framing.

Main training data = LLaVA-Video-178K

But split it internally into large pools:
caption
open-ended QA
multiple-choice QA
temporal-heavy QA
static/object/scene QA

Important:
"split" does not mean making a tiny 1k-2k subset.
It means building samplers over the large internal pools.

Stage 1: Graft warm-up

목표: Frozen SigLIP feature 위에 temporal thought graft와 projector가 LLM input으로 안정적으로 붙게 만든다.

data: captions + easy open-ended QA
loss: L_answer + L_semantic
encoder: Frozen SigLIP
LLM: Frozen
train: temporal thought graft + registers + projector

Stage 2: Nested prefix instruction tuning

목표: z1:z8, z1:z16, z1:z32, z1:z64가 모두 answer 가능한 prefix-valid thought가 되게 만든다.

data: open-ended QA + multiple-choice QA
k ∈ {8,16,32,64}
loss: L_answer + L_teacher_KL + L_order

Stage 3: Temporal-heavy refinement

목표: thought token이 단순 visual summary가 아니라 temporal video state를 담게 만든다.

data: motion/order/counting/state-change/causal questions 중심 filtering
sampling: temporal-heavy samples oversampled
loss: L_answer + L_teacher_KL + L_pred + L_order

4Concrete Step Schedule

TM2-lite first run 기준. 1 optimizer step은 global batch 128 video-text samples로 둔다. 학습 종료는 epoch보다 max_steps로 제어한다. 먼저 30k steps로 sanity check를 보고, prefix curve가 보이면 55k steps까지 확장한다.

Epoch warning

10 epochs = 125 steps처럼 보이면 full LLaVA-Video-178K를 학습하는 것이 아니다. epoch당 12.5 steps라는 뜻이고, global batch 128이면 dataloader에 실제로 들어간 데이터가 약 12.5 × 128 = 1,600 samples뿐이라는 신호다. TM2 curriculum의 "나눠서 학습"은 작은 subset을 10 epoch 반복하라는 뜻이 아니라, 큰 caption/openQA/MCQA/temporal-heavy pool에서 정해진 비율로 계속 sample하라는 뜻이다.

steps_per_epoch = len(train_dataset_or_pool) / global_batch
total_steps = steps_per_epoch × epochs

If total_steps is tiny:
check max_steps, limit_train_batches, debug_subset,
and whether only one small filtered json was loaded.

5Which Samples Matter Most

good

TM2-lite에 중요한 subset

  • temporal order
  • action transition
  • object state change
  • counting over time
  • before/after
  • causal relation
  • multi-event summarization
less useful

너무 많이 섞으면 약해지는 subset

  • static scene description
  • single-frame object recognition
  • generic caption-only samples

6Loss Design

데이터 curriculum과 loss는 같이 가야 한다. LLaVA-Video-178K는 thought token 자체를 supervise하지 않으므로, teacher distillation과 prefix-order pressure가 필요하다.

L = L_answer
  + λ_kl L_teacher
  + λ_order L_prefix_order
  + λ_sem L_semantic
  + λ_pred L_temporal_prediction
CE

Answer loss

Video understanding task의 main objective. 답을 못하면 thought가 의미 없다.

KL

Teacher distillation

Dense visual-token teacher의 판단을 few thought tokens로 압축하게 만든다.

Order

Prefix order loss

긴 prefix가 짧은 prefix보다 더 못하면 penalty를 준다.

7Train / Eval Split

Training은 LLaVA-Video-178K 하나로 시작해도 된다. 다만 evaluation은 별도 benchmark로 보고, LLaVA-Video-178K repo 안에 포함된 public QA split과 겹치지 않게 관리해야 한다.

LLaVA-Video-178K

Eval:

Leakage risk

LLaVA-Video-178K repository에는 NeXT-QA, ActivityNetQA, PerceptionTest 같은 public QA도 재현용으로 같이 들어가 있다. train에 쓴 split과 eval benchmark가 겹치면 결과가 방어되지 않는다. 논문에서는 train source, held-out split, evaluation-only benchmark를 명확히 적어야 한다.

8Final Recommendation

LLaVA-Video-178K 하나로 시작해도 된다. 대신 random mixing이 아니라 caption/openQA/MCQA/temporal-heavy로 curriculum을 짜고, 후반에는 temporal-heavy sample을 oversampling한다. 첫 sanity check는 30k steps, 제대로 된 first run은 55k steps로 두고, 이 위에 teacher distillation, nested prefix loss, temporal prediction loss를 같이 걸어야 Thought Matryoshka의 핵심 claim이 살아난다.
Short version: use LLaVA-Video-178K as the main instruction-alignment data, not as an unstructured random pool. Split it by task type, over-sample temporal-heavy QA late in training, and evaluate on clean held-out video understanding benchmarks.
