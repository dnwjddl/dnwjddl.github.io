Ponder (working title)

Thinking While Watching: Event-Gated Latent Comprehension as the Video Representation

Research plan · 작성 2026-08-20 · 자매 문서: comparison 서베이 · Scribe (독립 프로젝트 — 겹치지 않음)

사람은 질문을 받고 나서야 영상을 처음 생각하지 않는다 — 보는 동안 이미 이해(situation model)를 구성하고, 질문은 그 이해 위에서 푼다. Ponder는 이 "보면서 생각하기"를 encoder 쪽에 둔다: LLM이 patch를 읽고 추론하는 대신, encoder가 사건 단위의 latent thought를 만들고 LLM은 그 생각만 읽는다. 생각의 개수는 사람이 정하는 비율이 아니라 예측이 깨지는 순간(사건 경계)이 결정한다.

1Overview

2Abstract (초안)

Video LLMs make language models do perception's job twice: an encoder turns every frame into patch tokens, and the LLM must then re-read thousands of them to reconstruct what happened before it can reason. Humans work differently — comprehension is built while watching, as a compact situation model updated at event boundaries, and questions are answered from that model rather than from raw imagery. We present Ponder, which moves this process to the encoder. A lightweight comprehension module maintains a running situation model over streaming SigLIP features and predicts what comes next; whenever prediction fails — the signature of an event boundary — it writes a new latent thought. The video representation handed to the LLM is just this sequence of timestamped thoughts: typically tens of tokens rather than thousands, with a count determined by the video's eventfulness rather than a preset ratio. Thoughts are trained without any chain-of-thought or caption supervision, using a predictive-state objective — thoughts must suffice to predict future features — combined with diversity regularization and answer likelihood through the frozen LLM. Because thoughts are question-agnostic, they are computed once per video and amortized across queries, and they compose with decode-time latent reasoning for multiplicative savings. 국문 요지. 지금의 Video LLM은 지각의 일을 두 번 시킨다 — encoder가 모든 프레임을 patch로 바꾸고, LLM이 그 수천 개를 다시 읽으며 "무슨 일이 있었는지"를 재구성한 뒤에야 추론을 시작한다. 사람은 반대다: 보는 동안 사건 경계마다 갱신되는 압축된 이해(situation model)를 만들고, 질문은 그 이해 위에서 푼다. Ponder는 이 과정을 encoder로 옮긴다. 경량 comprehension 모듈이 streaming feature 위에서 다음을 예측하다가, 예측이 깨지는 순간(사건 경계)에만 latent thought를 기록한다. LLM에 전달되는 표현은 timestamp가 달린 thought 수십 개가 전부다 — 개수는 사전 비율이 아니라 영상의 사건 밀도가 정한다. thought는 CoT·캡션 감독 없이, "미래 feature를 예측하기에 충분한 상태"라는 predictive-state 목적으로 학습된다.

Contribution 후보
  1. Thoughts, not patches — 비주얼 patch 토큰이 아니라 encoder가 만든 latent thought가 LLM의 비디오 입력이 되는 표현 체계. prefill 수천 → 수십 토큰.
  2. Event-gated emission — "언제 생각할지"를 running situation model의 예측 오차가 결정. 비율·개수 하이퍼파라미터 없이 완전 content-adaptive한 토큰 수 (인지과학의 event segmentation을 메커니즘으로 구현).
  3. Predictive-state 학습 — CoT도 캡션도 없이: thought들이 미래를 예측하기에 충분한 최소 상태가 되도록 학습 (rate = thought 수, distortion = 미래 예측 + 답변 likelihood). InfoTok(ICLR 2026 Oral)의 rate–distortion 정식화를 재활용.
  4. 직교성 증명 — 입력 측 절약(Ponder)과 출력 측 latent reasoning(VideoLatent류)이 결합되어 곱셈 이득을 냄을 실증.

4방법 스케치

  • Comprehension 모듈: SigLIP 중간층 feature 위 2–4층 transformer + 순환 상태. 세그먼트 단위 스트리밍으로 동작하며 host(encoder·LLM)는 frozen — 플러그인.
  • Running situation model: 현재까지의 thought들 {z₁…z_k}와 순환 상태로 다음 세그먼트의 feature를 예측 (TD-JEPA식 k-step latent 예측).
  • Event-gated writer: 예측 오차가 적응 임계(EMA 기반 z-score)를 넘으면 새 thought z_{k+1}을 cross-attention readout으로 기록. 오차가 낮은 동안은 아무것도 방출하지 않음 — 개수 M은 사건 밀도가 결정. 상한 M_max만 서빙용으로 둠 (adaptive-up-to-cap).
  • 학습 (CoT·캡션 무감독): L = ① predictive-state loss (thought들이 미래 feature를 예측하기에 충분하도록; collapse 방지 negative는 타 영상 세그먼트) + ② diversity loss (thought 간 유사도 벌점 — VideoLatent의 검증된 부품) + ③ answer CE (frozen LLM + 소형 projector 통과) + ④ rate 항 λ·E[M] (InfoTok ELBO식). 이산 게이트 gradient는 Rotation Trick, 게이트 붕괴는 rate 항과 load-balancing으로 견제.
  • LLM 소비: thought를 projector로 LLM 공간에 투영, 위치는 사건 구간의 timestamp (M-RoPE 좌표) — [z₁@0:00–0:41] [z₂@0:41–0:55] …. 질문 의존 추론은 전부 LLM에 남김.
  • 선택 확장: (a) 출력 측 latent reasoning(VideoLatent식)과 결합 — E6, (b) 신뢰도 낮으면 해당 사건 구간의 비주얼 토큰 재열람 — 최소 형태로만 (Scribe와의 차별 유지).

두 번째 설계 — Ponder-B: surprise 없이 (Ordered Thoughts + Truncation)

동기. surprise 게이트(Ponder-A)는 predictor 학습·임계 튜닝·event boundary 검증까지 부대 비용이 크다. Ponder-B는 "언제 생각할지"의 결정 기계를 제거하고, 결정을 "어디서 자를지"라는 싼 문제로 치환한다.

  • 방출: M_max개(예: 64) learnable thought query가 영상/세그먼트 feature에 cross-attention하는 1-pass 병렬 readout — 순환·AR·게이트 없음.
  • 순서 학습: nested tail-drop — 학습 시 절단점 m을 랜덤 샘플해 앞 m개 thought만으로 answer CE를 최적화. gradient가 중요 정보를 앞 slot으로 밀어 thought가 중요도 순으로 정렬됨 (Matryoshka·VaporTok taildrop·Progressive Compression의 prefix-유효 원리).
  • 개수 결정 (추론, 모델 추가 없음): ① 에너지 컷 — slot attention 질량이 순서 따라 감소, 임계 τ 아래에서 절단 · ② prototype 중복 제거(MetaSlot식) — 같은 프로토타입 slot 병합, 개수 = 서로 다른 내용 수 · ③ anytime 모드 — 앞 k개만 사용 (서빙 budget 즉응).
  • timestamp는 공짜: 각 slot의 attention 분포에서 시간 중심·범위 추출 → surprise 없이 M-RoPE 좌표 부여.
  • 학습 목적함수: answer CE + diversity + (선택) predictive-state — predictor를 완전히 빼면 감독은 QA쌍만으로 충분.

전략: 구현·검증이 싼 B를 먼저 세워 "thoughts-not-patches" 자체를 입증하고, A(게이트)는 B 위의 업그레이드/ablation으로 배치 — A가 B를 못 이기면 B 단독으로도 논문 성립.

왜 "지각 요약"이 아니라 "예측 상태"인가 (핵심 설계 논거)

Video-XL·Quicksviewer·LARP의 summary 토큰은 "지금까지 본 것을 잘 담기"(재구성 지향)를 배운다. Ponder의 thought는 "앞으로 올 것을 설명하기에 충분한 최소 상태"를 배운다 — world model의 상태 정의 그 자체다. 이 차이가 만드는 것: ① 재구성에 필요한 지엽적 외형은 버려지고 인과·동역학 구조가 남는다 → reasoning 벤치마크에 유리하다는 가설(E1·E5에서 검증), ② 예측 오차라는 게이트 신호가 목적함수에서 공짜로 나온다 → 별도 saliency 모듈 불필요, ③ 사건 경계 = 예측 실패 지점이라는 인지과학(event segmentation theory)적 근거.

5실험 계획

E1 — Main: reasoning 중심 Pareto

주장: prefill 1–3% budget으로 full-token과 대등, reasoning 벤치에서는 압축 baseline보다 우위.

  • 이해: VideoMME, MLVU, LongVideoBench, MVBench · 추론: VideoMathQA, MMVU, TempCompass, TOMATO
  • Baselines: full tokens / 압축 계열 동일 budget (FastVID·HoliTom·VidCom²·VisionZip) / summary-token 계열 (Video-XL, LLaMA-VID 재현) / LangDC식 caption 압축 / VideoLatent (출력 측)

E2 — Event-gate의 존재 증명

주장: thought 수 M이 정말 사건 밀도를 따라간다.

  • 영상 유형별 M 분포 (정적 vlog vs 스포츠 vs 영화) + M vs 장면 전환 수·motion energy 상관
  • 같은 영상 1×/2× 재생 대조: 내용이 같으면 M도 유사해야 (입력 길이 기반 가변과의 구분)
  • 방출 시점 vs 사람의 event boundary annotation (기존 event segmentation 데이터) 일치도 — 인지과학 주장의 직접 검증

E3 — Ablations

  • A vs B: surprise-gated(A) vs ordered+truncate(B) vs 고정 stride vs 무작위 방출 — 같은 평균 M에서 정면 비교 (B가 기본, A는 업그레이드 가설)
  • B의 컷 규칙: 에너지 컷 vs prototype 중복 제거 vs 고정 k (anytime)
  • 목적함수: predictive-state 제거(align만) / diversity 제거 / answer CE 제거 — 각각 collapse·성능 기여 분리
  • predictor horizon k, 임계 z-score, M_max, thought 차원
  • summary-지향 학습(재구성 loss)으로 바꿨을 때 reasoning 벤치 하락 여부 — "예측 상태 > 지각 요약" 가설의 직접 검증

E4 — Thought probing (분석 섹션)

  • linear probe: thought에서 객체/행동/장소/순서 정보 복원 가능성 — situation model의 차원(누가·무엇을·어디서·언제)이 실제로 담기는가
  • thought 하나 제거 시 어떤 질문이 깨지는지 — 사건-질문 대응의 인과 분석
  • 인접 thought 보간이 중간 사건을 표현하는가 (latent 공간의 구조성)

E5 — 직교성: 출력 측 latent reasoning과 결합

  • Ponder(입력) × VideoLatent식 latent CoT(출력) 조합의 E2E 비용·정확도 — "곱셈 이득" 클레임 실증
  • Amortization: 영상당 다중 질문 시 비용 곡선 (질문 조건부인 VideoLatent 단독 대비)

E6 — 효율

  • prefill 토큰 수·TTFT·FLOPs·메모리, 1시간 영상 스트리밍 처리 (comprehension 모듈은 상수 메모리)
  • comprehension 모듈 비용 vs 절약된 prefill 수지표

구현 계획 (1차 세팅)

  • Host: Qwen2.5-VL-7B (VideoLatent과 직접 비교 가능) + LLaVA-OneVision-7B (압축 baseline과 비교 가능) — 기존 video-llm-eval 하네스 재사용.
  • 모듈: 2–4층 transformer(~50–100M) + GRU식 순환 상태 + M_max=64 thought slot.
  • 학습 (B 우선): Stage 1 — thought query + tail-drop + answer CE (LLaVA-Video-178K QA; predictor 불필요). Stage 2 — diversity + (선택) predictive-state 추가로 A 업그레이드 검증. Stage 3 — rate/절단 정책 정교화.
  • 데이터: 무라벨 영상 (Stage 1) + LLaVA-Video-178K (Stage 2) — CoT·캡션 생성 불필요가 그대로 비용 절감.

리스크와 대응

  • R1 Latent collapse (전 영상이 비슷한 thought) → diversity loss + 타 영상 negative + E4 probing으로 조기 감지
  • R2 LLM이 thought를 못 읽음 → Stage 2의 answer CE가 정렬을 강제; 실패 시 SPAE식 어휘 anchoring 추가
  • R3 세밀 지각 질문(OCR·counting)에서 붕괴 → 선택 확장 (b) 재열람으로 방어; 최악에는 "reasoning 특화 표현"으로 클레임 축소
  • R4 선점 위험 — DyLaR(2026.08)가 LLM 측에서 latent 개수 적응을 시작; encoder-side가 비어 있는 지금 빠르게 선행 공개(arXiv) 필요
  • R5 예측이 쉬운 지루한 영상에서 M→0 붕괴 → M 하한(구간당 최소 1) + rate 항의 양방향 견제
