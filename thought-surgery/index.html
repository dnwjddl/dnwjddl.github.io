Thought Surgery (working title)

Causal Situation Tokens: Building, Editing, and Testing the Video Thoughts an LLM Reads

Research plan · 작성 2026-08-23 · 자매 아이디어: Thought Matryoshka

Thought Matryoshka가 "생각을 중요도 순 prefix로 접자"라면, Thought Surgery는 더 과감하다: 비디오를 등장 단위, 사건 단위, 관계 단위의 latent situation graph로 만들고, 그 thought를 하나씩 빼고, 바꾸고, 이식했을 때 LLM의 답이 예측 가능하게 바뀌는지 본다. 즉 목표는 단순 압축이 아니라 수술 가능한 reasoning unit을 만드는 것이다.

1Intuition

왜 이해가 어려웠는가

"latent thought"라고만 말하면 그냥 압축 토큰처럼 들린다. Thought Surgery의 핵심은 thought에 역할을 주는 것이다. 하나의 thought가 "비디오 전체 요약"이 아니라, 어떤 것은 누가/무엇이 있었는지, 어떤 것은 무슨 일이 일어났는지, 어떤 것은 무엇이 먼저였고 무엇이 원인이었는지를 맡는다.

일반 Video LLM

LLM은 수천 개 patch token을 받고, 그 안에서 사람, 물체, 행동, 순서, 원인을 모두 다시 찾아야 한다. 답이 틀려도 어떤 정보가 빠졌는지 알기 어렵다.

patch1, patch2, patch3, ... → LLM → answer

Thought Surgery

encoder가 먼저 상황 구조를 만든다. LLM은 raw patch가 아니라 typed thought graph를 읽는다. 틀렸을 때는 thought를 조작해서 어느 단위가 답을 결정했는지 검사한다.

entities + events + relations → LLM → answer

이름의 의미
Remove
특정 thought를 제거한다. 관련 질문만 틀리고 무관한 질문은 유지되면, 그 thought가 실제로 국소적 역할을 한 것이다.
Swap
두 event thought의 순서나 relation thought를 바꾼다. before/after 질문의 답이 함께 바뀌면, 시간 관계가 thought 안에 들어 있다는 증거다.
Transplant
다른 비디오의 event 또는 relation thought를 이식한다. 답이 그 이식된 상황에 맞게 바뀌면, thought가 단순 noise가 아니라 편집 가능한 의미 단위라는 뜻이다.

2Overview Architecture

3Abstract (초안)

Video LLMs are accurate when enough visual tokens are passed forward, but their internal video state is hard to audit: if a temporal or causal question fails, we rarely know whether the model missed an entity, confused an event, or relied on the wrong relation. We propose Thought Surgery, a causal latent interface for video reasoning. Instead of compressing a video into an untyped set of visual tokens, the encoder constructs a latent situation graph made of entity thoughts, event thoughts, and relation thoughts. These continuous tokens are projected to the LLM as a compact, question-agnostic video memory. The central test is surgical: remove one thought, swap two relations, or transplant an event from a matched counterfactual video, and the LLM's answer should change only when the edited thought is relevant. Training combines object-centric video slots, event-state prediction, answer likelihood, full-token teacher distillation, and surgical consistency losses induced by temporal reversal, segment shuffling, masking, and counterfactual pairs. The result is not just a smaller video representation, but an editable reasoning interface whose failure modes can be localized at the level of entities, events, and relations.

국문 요지. Thought Surgery는 "토큰을 줄였다"에서 끝나지 않는다. 줄어든 토큰 하나하나가 어떤 역할의 생각인지를 가져야 한다. 그래서 encoder는 비디오를 entity event relation thought로 나누고, LLM은 이 latent graph를 읽는다. 이후 thought를 하나 제거하거나 순서를 바꾸거나 다른 비디오에서 가져와 이식한다. 답이 그 조작에 맞게 국소적으로 바뀌면, 그 thought는 실제 reasoning unit으로 인정된다.

4Contributions

Typed thoughts
모든 latent를 같은 "summary token"으로 보지 않고 entity, event, relation으로 타입화한다. 이것이 LLM에게 더 맞는 video interface다.
Causal auditability
정답률만 보는 대신, thought를 조작했을 때 답이 어떻게 바뀌는지 측정한다. 모델 내부 representation의 책임 소재를 찾는 실험이 된다.
Counterfactual training
reverse, shuffle, mask, matched pair 같은 비디오 변환으로 surgical consistency를 학습한다. 즉 "수술"은 분석만이 아니라 학습 신호다.
Bridge to reasoning
object-centric learning은 보통 segmentation/tracking에서 끝난다. 여기서는 object/event/relation thought가 LLM 답변의 입력 단위가 된다.

5Method

5.1 Entity Thought: 누가/무엇이 있었는가

  • Slot Attention/SAVi 계열처럼 video feature에서 persistent slot을 뽑는다. 단 목적은 예쁜 segmentation mask가 아니라 LLM이 읽을 entity memory를 만드는 것이다.
  • 각 entity thought는 soft spatial mask, time span, appearance state, motion state를 갖는다.
  • 좋은 entity thought는 같은 대상이 화면에서 이동해도 같은 slot으로 유지되어야 한다. temporal consistency와 contrastive tracking loss를 사용한다.

5.2 Event Thought: 무슨 변화가 있었는가

  • event는 entity state가 바뀌는 구간이다. 예: 한 대상이 이동 방향을 바꿈, 두 대상이 접촉함, 어떤 상태가 열림/닫힘으로 바뀜.
  • event inducer는 인접 시간의 entity state 차이를 보고 event slot v_i를 만든다.
  • 학습은 future entity-state prediction으로 시작한다. 좋은 event thought는 다음 상태를 예측하는 데 필요한 변화 정보를 담아야 한다.

5.3 Relation Thought: 무엇이 먼저이고 무엇이 원인인가

  • relation thought는 event 사이의 edge다. 가장 기본은 before/after, 더 강한 버전은 cause/enables/prevents까지 간다.
  • 초기에는 causal을 너무 세게 주장하지 않고, temporal relation부터 검증한다. temporal relation이 안정되면 cause/effect benchmark로 확장한다.
  • LLM 입력에는 continuous relation token과 가벼운 type tag를 함께 넣는다. 자연어 caption이 아니라, LLM embedding space의 structured latent memory다.

5.4 Surgical Consistency Loss

Thought Surgery의 논문성이 생기는 지점이다. "이 thought가 중요해 보인다"가 아니라, 그 thought를 조작하면 답이 예측한 방향으로 바뀌어야 한다고 학습하고 평가한다.

L = L_QA + α L_teacher + β L_track + γ L_event + δ L_surgery

Thought Matryoshka와의 관계

Thought Matryoshka는 더 안전한 메인 아이디어다: ordered prefix가 성능/효율 Pareto를 만든다. Thought Surgery는 더 risk가 높지만, 성공하면 더 깊다: thought가 진짜 reasoning unit이라는 것을 intervention으로 보인다. 현실적인 논문 전략은 Matryoshka를 backbone으로 두고, Surgery를 analysis 또는 advanced variant로 붙이는 것이다.

7실험 계획

E1 — Main: reasoning accuracy with typed thoughts

주장: typed situation graph는 같은 token budget에서 untyped resampler나 pruning보다 temporal/causal reasoning에 강하다.

  • Benchmarks: MVBench temporal tasks, TempCompass, TemporalBench, LongVideoBench, CaST-Bench, CausalVQA.
  • Baselines: full visual tokens, fixed latent resampler, Thought Matryoshka untyped slots, object slots only, event-only, relation-free graph.
  • Metric: accuracy, prefill tokens, TTFT, graph size, entity/event/relation count.

E2 — Surgical locality

주장: thought 제거/교체의 영향이 관련 질문에만 국소적으로 나타난다.

  • Remove each entity/event/relation thought and measure answer delta by question type.
  • Locality score: relevant-question accuracy drop minus irrelevant-question accuracy drop.
  • Compare against random token removal and attention-based visual token removal.

E3 — Counterfactual controllability

주장: relation thought를 바꾸면 temporal/counterfactual answer가 예측 가능하게 바뀐다.

  • Reverse-video pair: before/after relation이 뒤집히는지 확인.
  • Segment shuffle: event order thought만 바뀌고 entity thought는 유지되는지 확인.
  • Matched transplant: 같은 배경/비슷한 entity 구성에서 event thought만 바꿨을 때 답이 따라오는지 확인.

E4 — Grounding and probing

주장: typed thought가 실제 video evidence에 grounded되어 있다.

  • Entity thought: mask/track IoU가 완벽하지 않아도 temporal consistency가 있는지 측정.
  • Event thought: action class, state-change, time span을 linear probe로 복원.
  • Relation thought: before/after, same-time, cause-like relation을 probe.
  • Failure report: 모델이 틀린 경우 entity miss, event miss, relation miss 중 어디인지 분해.

8구현 계획

Stage 0 — 최소 구현
  • Qwen2.5-VL 또는 LLaVA-OneVision의 frozen video feature 사용.
  • entity slot tracker 없이 먼저 event/relation typed query만 학습해 proof-of-concept 확인.
  • QA CE + full-token teacher distillation으로 LLM이 typed latent를 읽게 만든다.
Stage 1 — entity/event 분리
  • slot tracker를 붙여 persistent entity thought 생성.
  • entity state difference로 event thought 유도.
  • time span embedding과 soft mask supervision 없이 temporal consistency부터 확인.
Stage 2 — surgical training
  • reverse, shuffle, mask augmentation으로 relation swap/removal loss 구성.
  • counterfactual pair가 있는 benchmark에서는 supervised surgery loss 사용.
  • locality score가 오르는지 ablation.
Stage 3 — paper-grade analysis
  • 질문 유형별 failure attribution 표.
  • thought removal heatmap.
  • wrong answer를 고치는 transplant demo.

9리스크와 방어선

  • R1 Slot이 사람에게 해석 가능한 object로 안 나뉨. 완벽한 segmentation을 목표로 두지 말고, QA-relevant entity grouping과 temporal consistency를 metric으로 둔다.
  • R2 Causal이라는 말이 과장으로 보일 수 있음. 초반 claim은 temporal/relation-local intervention으로 제한하고, cause/effect는 CaST-Bench나 CausalVQA에서 별도 섹션으로 증명한다.
  • R3 LLM이 typed latent graph를 못 읽음. type tag는 discrete special token으로 주고, 실제 content는 continuous token으로 주는 hybrid interface를 사용한다.
  • R4 수술 결과가 불안정함. 단일 질문이 아니라 paraphrase group, matched counterfactual group, irrelevant-control question으로 locality를 측정한다.
  • R5 Matryoshka보다 구현 부담이 큼. 그래서 메인 논문으로 바로 밀기보다, Matryoshka backbone 위에 typed/surgery variant로 붙이는 전략이 현실적이다.
한 문장 버전: Thought Surgery turns video tokens into editable latent situation units, then proves their reasoning role by removing, swapping, and transplanting them. · 핵심 차별점: compression ratio가 아니라 surgical locality, 즉 특정 thought 조작이 관련 답에만 영향을 주는지다.
